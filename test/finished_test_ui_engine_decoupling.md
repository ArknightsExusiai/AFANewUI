# 测试清单：`test_ui_engine_decoupling`

> 对应更改：把**托盘所有权**抽成引擎无关的接缝，并加引擎分派入口（PR ①，为接入 web 引擎做前置解耦）。

### 流程：从更新弹窗打开设置界面

> 涉及模块：`updater_ui.ahk`、`ui_shell.ahk`、`gui.ahk`
> 为什么测：`SettingsShowRequested` 的**订阅方从 `gui.ahk` 搬到了 `ui_shell.ahk`** —— 这是本轮唯一一处"事件订阅搬家"，是本阶段最大的回归风险点。
>
> **已跳过（无法按需触发）**，原因与残余风险记录如下：
>
> - `SettingsShowRequested` 全工程**只有一处发布**（`updater_ui.ahk:182`），触发条件是：手动检查更新 → 状态为 `rate_limited` → 且 `suggestToken` 为真。
> - `suggestToken: true` **只在一种情况下设置**：`release_repository.ahk:96` 的 GitHub 未认证限流（60 次/小时配额耗尽）。`check_failed` / `token_invalid` 都不会给出这个入口（填假 Token 也走不到）。
> - 残余风险很小：① 它调用的 `UiShell.Show()` 已由托盘「打开设置界面」实际验证；② 订阅注册是 `UiShell.Start()` 里的 3 行，已被 `/Validate` + 冒烟测试覆盖加载；③ `event_contract_check` 已证明发布/订阅成对存在。未验证的只剩"运行时 EventBus 确实注册了该订阅"，与 `gui.ahk` 中另外 25 处订阅同机制。
> - 若日后要补验：把 GitHub 未认证配额点爆（连点「立即检查一次更新」数十次）逼出确认框，选「是」即可。

- [ ] **前置**：手动检查更新并进入「检查失败 + 建议配置 Token」确认框（需 GitHub 未认证限流）
- [ ] **操作**：在确认框上选「是（现在配置GitHub Token）」
- [ ] **预期**：设置窗口正常打开（且只打开一个）
- [ ] **操作**：关闭设置窗口，再重复一次
- [ ] **预期**：仍能正常打开（可重复）
